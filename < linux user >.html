الموسوعة الشاملة لهيكل لينكس

دليل يجمع بين النظرية المعمقة، والمفاهيم المتقدمة المخفية، والسيناريوهات العملية الميدانية لسطر الأوامر.

1. الفلسفة الأساسية

  • كل شيء هو ملف: المستندات، الأجهزة المادية (القرص الصلب، المنافذ التسلسلية)، ومعلومات النواة (Kernel) والعمليات تمثل كملفات.
  • شجرة مقلوبة مفردة: لا يوجد أقراص منفصلة. يبدأ النظام من الجذر (/). الأقراص الجديدة تُربط (Mount) كفروع داخلها.
  • حساسية حالة الأحرف: File يختلف عن file.

2. المعيار القياسي (FHS)

موثق في معيار FHS (Filesystem Hierarchy Standard) ليضمن توافق البرامج عبر جميع توزيعات لينكس اليونكسية.

مفهوم متقدم: ما هي الـ Inodes؟

عند إنشاء ملف، لا يخزن لينكس الاسم والمحتوى معاً. بل يُنشئ "بطاقة هوية" تسمى Inode تحتوي على: الصلاحيات، المالك، الحجم، ومؤشرات إلى مواقع البيانات الفعلية على القرص الصلب.

الخلاصة: الملف الذي تراه في المجلد هو مجرد "وصلة" تشير إلى رقم الـ Inode. إذا امتلأت مساحة الـ Inodes (رغم وجود مساحة فارغة)، لن تستطيع إنشاء ملفات جديدة! (يحدث كثيراً مع ملفات السجلات الصغيرة جداً).

3. شرح تفصيلي لمجلدات الجذر (/)

/bin & /sbinالملفات التنفيذية

/bin أوامر للمستخدمين. /sbin أوامر لمدير النظام Root.

🌍 تطبيق: معرفة مكان الأمر

which ls
which python3
/bootملفات الإقلاع

يحتوي على النواة (vmlinuz) والـ initramfs و GRUB. مسحه يعني تدمير قدرة النظام على الإقلاع.

/devملفات الأجهزة

تمثيل الأجهزة كملفات (مثل /dev/sda).

🌍 تطبيق: عرض الأقراص المتصلة

lsblk

🌍 تطبيق: إخفاء المخرجات (الثقب الأسود)

ping google.com > /dev/null
/etcملفات الإعدادات

ملفات نصية تتحكم في النظام.

🌍 تطبيق: تغيير اسم الجهاز

cat /etc/hostname
sudo nano /etc/hostname
/home & /rootالمنازل الشخصية

/home/user للبيانات الشخصية. /root منزل المدير، يقع خارج home لضمان عمله حتى لو تعطل قسم المنازل.

/libالمكتبات المشتركة

تشبه DLLs في ويندوز. مكتبات لتشغيل أوامر /bin. يحتوي أيضاً على مشغلات النواة في /lib/modules/.

/usrموارد يونكس

ثاني أكبر هيكل. يحتوي على التطبيقات غير الأساسية للإقلاع.

تطور حديث: في التوزيعات الحديثة، أصبح /bin مجرد رابط يشير إلى /usr/bin لتبسيط النظام.
/varالبيانات المتغيرة

سجلات (/var/log)، مؤقتات (/var/cache).

🌍 تطبيق: مراقبة أعطال النظام لحظياً

sudo tail -f /var/log/syslog
/tmpالمؤقتات

يُحذف عند إعادة التشغيل. يطبق عليه Sticky Bit ليتمكن المستخدم من حذف ملفاته فقط.

/optاختياري

للبرامج الكبيرة أو التجارية التي تُثبت يدوياً خارج مستودعات النظام (مثل Chrome).

/media & /mntنقاط الربط

/media للتركيب التلقائي (GUI). /mnt للتركيب اليدوي (CLI).

/proc & /sysوهمية (Virtual)

تمثيل في الذاكرة (RAM) للنواة.

🌍 تطبيق: قراءة مواصفات العتاد

cat /proc/cpuinfo | grep "model name"
cat /proc/meminfo
/run & /lost+foundتشغيل ومفقودات

/run لبيانات التشغيل الحالية. /lost+found لشظايا الملفات المنقذة بعد انقطاع الكهرباء.

4. المسارات والتنقل

  • مسار مطلق: من الجذر /home/a/file.
  • مسار نسبي: من موقعك a/file.

اختصارات:

. (الحالي)  |  .. (الأب)  |  ~ (المنزل)  |  - (السابق)

🌍 إتقان التنقل الميداني

pwd          # أين أنا؟
ls -la       # عرض مفصل مع الملفات المخفية
cd /etc      # تنقل مطلق
cd ..        # خطوة للخلف
cd ~         # العودة للمنزل فوراً
cd -         # الرجوع للمجلد السابق فوراً

السر المحترف: وهم الامتدادات والـ Shebang

في ويندوز، يعتمد النظام على الامتداد (مثل .exe أو .mp3) ليعرف كيف يتعامل مع الملف. في لينكس، الامتداد غير مهم إطلاقاً للنظام. يمكنك تسمية ملف تنفيذي my_file.txt وسيعمل إذا كانت صلاحيات التنفيذ مفعلة!

كيف يعرف لينكس أي مترجم (Interpreter) يستخدم لتشغيل السكربت؟
عبر السطر الأول من الملف ويسمى Shebang #!.

تطبيق: إنشاء سكربت بايثون وسكربت بش

# سكربت باش (يبدأ بالمسار التالي)
#!/bin/bash
echo "Hello from Bash"

# سكربت بايثون (يبدأ بالمسار التالي)
#!/usr/bin/env python3
print("Hello from Python")

عند كتابة ./script.sh في الطرفية، يقرأ لينكس السطر الأول، يرى #!/bin/bash، فيقوم بتشغيل مترجم باش ويمرر له الملف ككل لتنفيذه.

السر المحترف: مديرو الحزم والتوزيع

عندما تكتب sudo apt install nginx (في أنظمة ديبيان)، ماذا يحدث في الهيكل الهرمي بالضبط؟ مدير الحزم يقوم بتوزيع الملفات المستخرجة من الحزمة بأتمتة كاملة وفق معيار FHS:

  • الملفات التنفيذية للبرنامج تُرسل إلى /usr/sbin/.
  • ملفات الإعدادات الخاصة بالبرنامج تُرسل إلى /etc/nginx/.
  • الصفحات الرئيسية لموقع الويب تُرسل إلى /var/www/html/.
  • ملفات السجل الخاصة بالبرنامج تُنشأ في /var/log/nginx/.
  • المكتبات الإضافية تُرسل إلى /usr/lib/.

لماذا هذا مهم؟ عندما تريد حذف البرنامج بالكامل، يكفي أمر apt remove nginx ليمسح أثره من كل هذه المجلدات. أما إذا قمت بتثبيت برنامج يدوياً (بالسحب والنسخ)، سيترك برامجاً أوتاراً (Orphan files) في كل مكان تسبب تضخم النظام.

السر المحترف: آلية الـ Mounting العميقة

كيف يتم ربط قرص فعلي (مثل /dev/sdb1) داخل شجرة المجلدات (مثل /mnt/usb)؟

تطبيق: الربط اليدوي

# 1. إنشاء نقطة الربط (المجلد)
sudo mkdir -p /mnt/usb

# 2. الربط الفعلي
sudo mount /dev/sdb1 /mnt/usb

# 3. الآن يمكنك التعامل مع الملفات داخل /mnt/usb كأنها على الفلاشة

# 4. لفصل الفلاشة بأمان (مهم جداً لعدم فقدان البيانات)
sudo umount /mnt/usb

الربط الدائم (/etc/fstab):
إذا أردت أن يربط النظام القرص تلقائياً عند كل إقلاع، لا تكتب أمر الربط يدوياً. بل تضيف سطراً في ملف /etc/fstab. تنسيق السطر هو:

# الجهاز        نقطة الربط     نوع النظام  الخيارات  تفريغ  فحص
/dev/sdb1       /mnt/mydisk    ext4        defaults   0       2

تحذير: خطأ في كتابة ملف /etc/fstab سيجعل النظام يدخل في حالة Emergency Mode ولن يستطيع الإقلاع! دائماً اختبر الربط يدوياً أولاً.

نظام الصلاحيات (rwx)

عند ls -l، الرموز مثل -rwxr-xr-- تعني:

  • - : نوع الملف (ملف عادي، أو d لمجلد).
  • rwx : المالك (قراءة، كتابة، تنفيذ).
  • r-x : المجموعة (قراءة، تنفيذ، بدون كتابة).
  • r-- : الآخرون (قراءة فقط).

تطبيق: التعديل بالأرقام (Octal)

# r=4, w=2, x=1
# المالك (7=4+2+1) | المجموعة (5=4+1) | الآخرون (4=4)
chmod 754 script.sh

الحماية المطلقة: الأمر chattr

هل تعلم أنه حتى المستخدم root (صاحب أعلى صلاحيات) يمكن إيقافه عن حذف أو تعديل ملف معين؟ يتم ذلك باستخدام "سمات الملفات" وليس الصلاحيات العادية.

تطبيق: تجميد ملف (جعله Immutable)

# إضافة سمة التجميد على ملف الإعدادات
sudo chattr +i /etc/resolv.conf

# الآن حتى Root لا يستطيع تعديله أو حذفه!
sudo rm /etc/resolv.conf # سيعطي خطأ: Operation not permitted

# لإزالة التجميد والعودة للوضع الطبيعي
sudo chattr -i /etc/resolv.conf

يُستخدم هذا بكثرة لحماية ملفات النظام الحرجة من البرامج الخبيثة أو الأخطاء البشرية، أو لمنع مديري الحزم من تبديل ملفات إعدادات الشبكة المخصصة.

الروابط (Links)

  • رابط ناعم (Symlink): اختصار. إذا حذفت الأصل، يتعطل. (يستخدم لربط /bin بـ /usr/bin).
  • رابط صلب (Hard Link): اسم ثاني للملف يشير لنفس الـ Inode. حذف الاسم الأصلي لا يحذف البيانات طالما يوجد رابط صلب.

تطبيق: إنشاء اختصار

ln -s /etc/passwd ~/Desktop/passwd_shortcut

5. أوامر الخريطة الكاملة

البحث عن ملف ضائع

sudo find / -name "config.ini" 2>/dev/null

معرفة المساحة الفارغة

df -h

حجم مجلد معين

sudo du -sh /var/log

6. القواعد الذهبية للسلامة

1. لا تستخدم sudo إلا للضرورة (عند التعديل في /etc مثلاً).
2. لا تنفذ هذا الأمر أبداً (يمسح النظام وهو يعمل): 
sudo rm -rf /
3. مجلدات /home/user و /tmp هي مناطق اللعب الآمنة. افعل ما شئت فيها.
